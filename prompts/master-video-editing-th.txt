# ==================================================
# BEFORE EDITING
# ==================================================

1. ตรวจ OS / Device จริงผ่าน Remote Desktop Commander ทุกครั้ง
2. ตรวจว่า CapCut เปิดอยู่และโปรเจกต์ที่ถูกต้องอยู่บน Timeline
3. อ่าน Timeline ล่าสุดก่อนแก้
4. ตรวจ Source / Target Range ปัจจุบัน
5. Backup Draft ก่อน direct write
6. ถ้าต้องถอดเสียง ให้ใช้ original continuous source media เป็นหลัก พร้อม word timestamps
7. ห้ามใช้ ASR หลัง jump cut เป็น primary transcript ถ้ายังมี source ต้นฉบับ

# ==================================================
# SPEECH EDITING
# ==================================================

เป้าหมาย:
ทำคลิปให้กระชับขึ้น แต่ยังฟังเป็นธรรมชาติและรักษาความหมาย

ลบได้เมื่อชัดเจนว่าเป็น:
- false start
- retake ที่ถูกแทนด้วย take ที่ดีกว่า
- count-in / off-take
- filler ที่ไม่มีความหมาย
- dead air ที่ไม่ช่วย pacing หรือ visual

ห้ามลบเพียงเพราะ:
- ประโยคซ้ำ
- มีช่วงเงียบ
- waveform เบา

ให้เก็บ repetition ถ้ายังทำหน้าที่:
- setup
- reasoning
- instruction
- transition
- proof
- CTA
- deliberate emphasis

Retake:
- เปรียบเทียบความสมบูรณ์ของประโยคและความต่อเนื่องของความหมาย
- ถ้ามีหลาย take ให้เก็บ take ที่ดีที่สุดและเป็นธรรมชาติที่สุด

หลัง picture edit:
- ตรวจ Timeline ใหม่
- remap subtitle จาก source range ที่ยังถูกเก็บจริง

# ==================================================
# SUBTITLE
# ==================================================

ใช้ tiktok-subtitle-sync

หลัก:
- Phrase First
- ห้ามแบ่งคำไทยกลางคำ
- ให้ซับตามจังหวะพูด ไม่อ่านนำเสียง
- รักษาความหมายของวลี
- หลัง lock timing แล้ว สามารถตัด filler ในข้อความเขียนออกได้ถ้าไม่เสียความหมาย
- ห้ามตัด negation, ตัวเลข, constraint, CTA, ชื่อเครื่องมือ/สินค้า หรือคำเตือน

ถ้ามี visual reference จากโปรเจกต์ล่าสุด ให้ clone style จากของเดิมก่อน

# ==================================================
# PUNCH ZOOM / VISUAL POLISH
# ==================================================

ทำหลัง Speech + Subtitle stable แล้ว

Punch Zoom ใช้เป็น punctuation ไม่ใช่ decoration

ใช้เมื่อ:
- Hook
- key number
- warning
- contrast
- conclusion
- CTA

อย่าใส่ทุกประโยค

Insert Planning:
- ใช้ visual เมื่ออธิบายได้เร็วกว่าคนพูด
- VDO เมื่อ motion/change over time สำคัญ
- รูป เมื่อภาพเดียวสื่อสารได้ครบ

# ==================================================
# SFX
# ==================================================

ทำเฉพาะเมื่อ TASK ระบุ

SFX ต้อง support visual trigger ไม่ใช่ใส่เพื่อความแน่น

ถ้ามีการ sync peak:
- วิเคราะห์ peak ของ SFX
- offset ให้ peak ตรง visual transition
- ห้ามให้ SFX กลบ dialogue

# ==================================================
# SAFE WRITE
# ==================================================

ก่อน direct write:
1. ปิด CapCut
2. Backup Draft แบบ versioned
3. อ่าน Draft ล่าสุด
4. แก้เฉพาะสิ่งที่อยู่ใน scope
5. Sync root / timeline / metadata ที่ schema ต้องการ
6. Validate ก่อนเปิด CapCut กลับ
7. เปิด CapCut แล้วตรวจว่า autosave ไม่เขียนทับ state ใหม่

ห้าม:
- ลบ user edit ที่ไม่ได้อยู่ใน scope
- สุ่มแก้ schema
- เขียนทับ local change ที่ไม่เกี่ยวข้อง
- สรุปว่างานเสร็จโดยไม่ตรวจ Draft จริง

# ==================================================
# QA / FINAL CHECK
# ==================================================

ตรวจอย่างน้อย:
- ความต่อเนื่องของความหมาย
- ไม่มีช่วงสำคัญหาย
- ไม่มีช่วงที่ผู้ใช้ลบถูกคืนกลับ
- source/target ranges ถูกต้อง
- duration ถูกต้อง
- subtitle ไม่เลย picture boundary แบบผิดพลาด
- subtitle timing ยังตรงหลัง ripple edit
- zoom อยู่ใน segment ที่ถูกต้อง
- insert / SFX ไม่เหลื่อมผิดจังหวะ
- root Draft และ Timeline Draft สอดคล้องกันเมื่อ schema ต้องการ
- CapCut เปิดกลับได้และ autosave ไม่ย้อนงาน
